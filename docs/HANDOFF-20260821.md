# W132D mainline handoff

## Baseline

- Target kernel: Linux v7.1, commit `8cd9520d35a6c38db6567e97dd93b1f11f185dc6`.
- Board: ZTE Cloud Computer W132D, Rockchip RK3528, 2 GiB RAM, 32 GiB eMMC.
- Boot chain: the verified vendor SPL/U-Boot is still used as a private,
  temporary input. This does not make the vendor kernel the runtime target.
- Console: UART0 at `0xff9f0000`, 115200 8N1.

## Confirmed mainline hardware

USB2, USB3, wired RMII Ethernet, UWE5622 Wi-Fi, and UWE5622 Bluetooth have
passed hardware testing on the current mainline image. eMMC rootfs boot is
stable after capping the controller at 52 MHz in 3.3 V MMC High-Speed mode.

Bluetooth is not a normal UART device. The WCN driver exposes the tty-over-SDIO
transport; `w132d-btattach` sends the controller initialization commands and
then attaches the H4 line discipline for BlueZ.

3.5 mm audio and infrared are explicitly dropped from the project scope.

## Snapshot boundary

The active public `main` branch intentionally omits the display path. Its DTS
does not instantiate a display subsystem or output endpoint, its boot templates
contain no display mode argument, and the kernel preparation script disables
the corresponding display options. This keeps the tested storage, USB,
Ethernet, Wi-Fi, and Bluetooth paths independent while display porting is
paused.

The previous vendor Linux 6.1 tree is preserved as branch `vendor-6.1`. Do not
copy its vendor device-tree nodes or modules into the Linux v7.1 build without
an explicit API and binding review.

## Wireless build boundary

The public tree contains only compatibility patches and build logic. The exact
UWE5621/UWE5631 source commits are archived into a private WSL staging area by
`scripts/prepare_wireless_mainline_wsl.sh`; firmware and calibration files are
extracted from a user-owned Android vendor image during local assembly. They
must not be committed or redistributed.

## Recommended next work

1. Keep this branch focused on regressions in eMMC, USB, Ethernet, Wi-Fi, and
   Bluetooth.
2. Develop the display path separately from this clean baseline, using the
   vendor DTB only as a register and wiring reference.
3. Evaluate mainline U-Boot independently after the kernel/peripheral baseline
   is stable.
