# W132D 主线移植交接

## 基线

- 目标内核：Linux v7.1，提交 `8cd9520d35a6c38db6567e97dd93b1f11f185dc6`。
- 板卡：ZTE Cloud Computer W132D，Rockchip RK3528，2 GiB 内存，32 GiB eMMC。
- 启动链：已验证的 vendor SPL/U-Boot 仍作为私有临时输入使用。这不改变主线内核作为运行时目标的事实。
- 控制台：UART0，基地址 `0xff9f0000`，115200 8N1。

## 已确认的主线硬件

USB2、USB3、RMII 有线网口、UWE5622 Wi-Fi 和 UWE5622 蓝牙已在当前主线镜像上通过硬件测试。将控制器限制在 3.3 V MMC High-Speed 模式、52 MHz 后，eMMC 根文件系统启动稳定。

蓝牙不是普通 UART 设备。WCN 驱动提供 tty-over-SDIO 传输；`w132d-btattach` 发送控制器初始化命令，然后挂载 H4 line discipline 供 BlueZ 使用。

3.5mm 音频和红外已明确从项目范围中放弃。

## 快照边界

当前公开的 `main` 分支有意省略显示路径。其 DTS 不实例化显示子系统或输出 endpoint，启动模板不包含显示模式参数，内核准备脚本也禁用对应显示选项。这样可以让已测试的存储、USB、网口、Wi-Fi 和蓝牙路径相互独立，同时暂停显示移植。

以前的 vendor Linux 6.1 树保存在 `vendor-6.1` 分支。未经明确的 API 和 binding 审查，不要把其中的 vendor 设备树节点或模块复制到 Linux v7.1 构建中。

## 无线构建边界

公开树只包含兼容补丁和构建逻辑。`scripts/prepare_wireless_mainline_wsl.sh` 会把精确的 UWE5621/UWE5631 源码提交归档到私有 WSL staging 目录；固件和校准文件则在本地组装时从用户拥有的 Android vendor 镜像提取。它们不得提交或再分发。

## 建议的后续工作

1. 继续以 eMMC、USB、网口、Wi-Fi 和蓝牙回归为主，保持此分支范围稳定。
2. 脱离这个干净基线单独开发显示路径，vendor DTB 只能作为寄存器和接线参考。
3. 待内核和外设基线稳定后，独立评估主线 U-Boot。

# W132D Mainline Handoff

## Baseline

- Target kernel: Linux v7.1, commit `8cd9520d35a6c38db6567e97dd93b1f11f185dc6`.
- Board: ZTE Cloud Computer W132D, Rockchip RK3528, 2 GiB RAM, 32 GiB eMMC.
- Boot chain: the verified vendor SPL/U-Boot is still used as a private, temporary input. This does not make the vendor kernel the runtime target.
- Console: UART0 at `0xff9f0000`, 115200 8N1.

## Confirmed Mainline Hardware

USB2, USB3, wired RMII Ethernet, UWE5622 Wi-Fi, and UWE5622 Bluetooth have passed hardware testing on the current mainline image. eMMC rootfs boot is stable after capping the controller at 52 MHz in 3.3 V MMC High-Speed mode.

Bluetooth is not a normal UART device. The WCN driver exposes the tty-over-SDIO transport; `w132d-btattach` sends the controller initialization commands and then attaches the H4 line discipline for BlueZ.

3.5 mm audio and infrared are explicitly dropped from the project scope.

## Snapshot Boundary

The active public `main` branch intentionally omits the display path. Its DTS does not instantiate a display subsystem or output endpoint, its boot templates contain no display mode argument, and the kernel preparation script disables the corresponding display options. This keeps the tested storage, USB, Ethernet, Wi-Fi, and Bluetooth paths independent while display porting is paused.

The previous vendor Linux 6.1 tree is preserved as branch `vendor-6.1`. Do not copy its vendor device-tree nodes or modules into the Linux v7.1 build without an explicit API and binding review.

## Wireless Build Boundary

The public tree contains only compatibility patches and build logic. The exact UWE5621/UWE5631 source commits are archived into a private WSL staging area by `scripts/prepare_wireless_mainline_wsl.sh`; firmware and calibration files are extracted from a user-owned Android vendor image during local assembly. They must not be committed or redistributed.

## Recommended Next Work

1. Keep this branch focused on regressions in eMMC, USB, Ethernet, Wi-Fi, and Bluetooth.
2. Develop the display path separately from this clean baseline, using the vendor DTB only as a register and wiring reference.
3. Evaluate mainline U-Boot independently after the kernel/peripheral baseline is stable.
