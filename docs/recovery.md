# 恢复与故障排查

系统无法启动或升级后出现故障时，先保存日志和数据，再使用可用版本的完整刷写包恢复。重新刷写会替换系统；安装步骤见[安装指南](install.md)。

## USB 刷写

| 现象 | 处理 |
|---|---|
| 下载包摘要不符 | 重新下载完整包，核对同一 Release 的 `SHA256SUMS` |
| `--dry-run` 失败 | 完整解压原包，检查文件是否缺失或被修改 |
| 找不到 USB 设备 | 检查数据线、端口、供电及下载模式按键时序；Linux 检查设备权限 |
| 检测到多台设备 | 断开其他 Rockchip 设备后重试 |
| Loader / MaskROM 切换超时 | 断电后重新进入下载模式，使用同一发布包重试 |
| 写入或回读失败 | 保持设备在下载模式，检查连接与供电后重新刷写 |
| 回读成功但无法启动 | 检查串口日志，尝试已知可用的旧版本，并确认设备硬件型号 |

脚本在写入或回读失败后不会自动重启设备。包内镜像按保留区间拆分，请使用配套脚本刷写。

## 只读回读

本包 loader 已在设备上运行时，可比较所有写入内容：

```sh
sudo ./flash.sh --verify-only
```

该命令不写入、不重启，也不切换设备模式。设备已重启时，需重新进入 MaskROM 并加载本包 loader，或按安装流程完整重刷。

## 启动与运行故障

系统仍可登录时，先查看：

```sh
systemctl --failed
journalctl -b -k
```

板级服务名称见[日常使用](usage.md#服务与配置)。内核崩溃信息可能保存在 `/sys/fs/pstore/` 或 `/var/lib/systemd/pstore/`；请在反复重启前备份。

无法进入系统时，使用串口收集从上电开始的 U-Boot 和内核输出。升级异常可按[升级指南](upgrades.md#返回-stable)返回 stable；无法登录时使用 USB 刷写恢复。

HDMI 无显示时，可先通过有线网络或串口登录，检查内核显示日志并尝试 1080p60。高分辨率模式的支持边界见[硬件支持](hardware.md#hdmi-分辨率)。

## 报告问题

提交问题时附上设备型号、Release 版本、`uname -a`、相关软件包版本、复现步骤，以及完整错误输出。刷写问题还需主机系统、工具版本和 USB 连接方式；显示问题请附显示器型号及分辨率、刷新率。
