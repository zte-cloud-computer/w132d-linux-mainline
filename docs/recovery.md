# 恢复与故障排查

保留可用版本的完整刷写包和个人数据备份。恢复通常需要重新刷写，会替换操作系统；硬件故障、供电或 USB 连接问题不属于软件能够保证恢复的范围。

| 现象 | 处理 |
|---|---|
| 校验和不符 | 停止刷写，重新下载完整包，核对版本与 SHA256 |
| 没有 USB 设备 | 检查数据线、端口、供电和针孔按键时序；Linux 检查访问权限 |
| 多台设备 | 断开其他 Rockchip 设备后重试；脚本拒绝自动选择 |
| 模式切换超时 | 断电后重新进入下载模式；不要使用未知厂商 Loader 直接写大文件 |
| 回读失败 | 保持设备在 loader 模式，检查连接后重刷；脚本不会自动重启 |
| 回读通过但无法启动 | 检查供电和串口日志，保留发布清单、启动日志及 pstore；尝试已验证的旧发布包 |

```sh
# Compare all written bytes without writing or rebooting
sudo ./flash.sh --verify-only
```

`--verify-only` 要求本发布包的 loader 已运行；它不会自动改变下载模式。若设备已经重启，需要重新进入 MaskROM 并下载包内 loader 后再回读，或执行完整重刷。刷写失败报告应包含包版本、平台、工具版本、完整英文错误输出和连接方式。

针孔按键的目标是进入 Rockchip 下载模式。厂商系统和本项目 U-Boot 可能先进入不同模式；脚本处理 Loader 到 MaskROM 的转换。不要假设任意状态下按键都必然成功，更不要在供电不稳时反复擦除。

内核启动问题可查看串口、`journalctl -b -k`、`/sys/fs/pstore/` 和 `/var/lib/systemd/pstore/`。本项目保留早期 ramoops 日志；记录问题前先备份它们，避免后续启动覆盖。
